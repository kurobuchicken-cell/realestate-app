仕様書 realestate-app

最終更新: 2026-06-22

1. 概要

Supabase 認証付きの不動産検索 Web アプリ。メール＋パスワードで会員登録・ログインし、 ログインユーザーごとに物件情報を登録・編集・削除・一覧表示できる。

  • フロントエンド: React 18 + Vite
  • 認証 / DB: Supabase（Auth + Postgres + RLS）
  • ルーティング: React Router v6
  • スタイル: CSS Modules（ページ単位で *.module.css）
  • 本番URL: https://realestate-app-one-eta.vercel.app/login（Vercel）
  • Supabaseプロジェクト名: realestate-app

2. 画面構成・画面仕様

パス画面アクセス制限状態
/（/login へリダイレクト）-実装済
/loginログイン誰でも実装済
/register会員登録誰でも実装済
/properties物件一覧（CRUD）ログイン必須実装済

2.1 ログイン画面（LoginPage）

  • 入力: メールアドレス・パスワード
  • 送信成功時: /properties に遷移
  • 失敗時: 「メールアドレスまたはパスワードが正しくありません」を表示
  • 会員登録画面へのリンクを表示

2.2 会員登録画面（RegisterPage）

  • 入力: メールアドレス・パスワード（6文字以上）・パスワード（確認）
  • バリデーション: パスワード一致チェック、6文字以上チェック（クライアント側）
  • 登録成功時: フォームを隠し「確認メールを送信しました」というメッセージを表示 （Supabase側でメール確認が有効な場合の挙動を想定）
  • ログイン画面へのリンクを表示

2.3 物件一覧画面（PropertiesPage）

  • ヘッダー: アプリ名、ログイン中のメールアドレス、ログアウトボタン
  • 物件をカード形式（グリッドレイアウト）で表示。各カードに物件名・エリア・家賃（カンマ区切り）・間取りバッジを表示
  • 「＋ 物件を登録」ボタン → 新規登録モーダル（PropertyForm）を開く
  • 各カードに「編集」「削除」ボタン
  • 物件0件のとき: 空状態メッセージ＋「最初の物件を登録する」ボタンを表示
  • 取得失敗時: エラーバナーを表示
  • 削除時: 確認ダイアログなしで即削除（失敗時は alert でエラー表示）

2.4 物件登録・編集モーダル（PropertyForm）

  • 入力項目: 物件名・家賃（円・数値）・エリア名・間取り
  • 新規登録・編集を共用（property プロパティの有無でモード切替）
  • 全項目必須。未入力時は「すべての項目を入力してください」を表示
  • 背景クリックまたは✕ボタンで閉じる

3. 認証フロー

App.jsx
 └─ AuthProvider (AuthContext)   ← Supabase セッションをグローバル管理
     └─ BrowserRouter
         ├─ /login       → LoginPage
         ├─ /register    → RegisterPage
         └─ /properties  → PrivateRoute → PropertiesPage
  • AuthContext が supabase.auth.onAuthStateChange を購読し、 user と loading をアプリ全体に提供する
  • PrivateRoute は loading === true の間は何も描画せず、 セッション確認完了後に未ログインなら /login へリダイレクトする
  • 提供されるAPI: signUp(email, password) / signIn(email, password) / signOut()

4. データモデル（Supabase）

4.1 properties テーブル

カラム型制約説明
iduuidprimary key, default gen_random_uuid()物件ID
user_iduuidnot null, references auth.users(id) on delete cascade登録者ID
nametextnot null物件名
rentintegernot null, check (rent >= 0)家賃（円）
areatextnot nullエリア名
room_typetextnot null間取り（例: 1LDK）
created_attimestamptznot null, default now()登録日時

4.2 RLS（行レベルセキュリティ）ポリシー

操作ポリシー名条件
select自分の物件のみ参照可能auth.uid() = user_id
insert自分のuser_idで登録可能auth.uid() = user_id（with check）
update自分の物件のみ更新可能auth.uid() = user_id（using / with check）
delete自分の物件のみ削除可能auth.uid() = user_id

定義ファイル: supabase/schema.sql（Supabaseダッシュボード SQL Editor で実行）

5. API（propertiesApi.js）

関数内容
fetchProperties()自分が登録した物件を created_at 降順で取得
createProperty({ name, rent, area, room_type }) auth.getUser() で取得した user_id を付与して新規登録
updateProperty(id, { name, rent, area, room_type })指定IDの物件を更新（RLSで自分の物件のみ）
deleteProperty(id)指定IDの物件を削除（RLSで自分の物件のみ）

9. 既知の制約・今後の課題

  • 物件削除時に確認ダイアログがない（誤操作で即削除される）
  • 画像登録機能がなく、カードはプレースホルダー（🏠アイコン）表示のみ
  • 物件の検索・絞り込み機能は未実装（一覧表示のみ）
  • 会員登録後のメール確認フローはSupabase側の設定（メール確認の有効/無効）に依存しており、本コードでは制御していない
  • テスト: @playwright/test が devDependencies に追加済みだが、テストコード自体は未作成
